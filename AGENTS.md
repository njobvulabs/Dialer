# AGENTS.md

Multi-module Android app (**Jetpack Compose**, Kotlin) tracking `main` with git remote
`origin https://github.com/njobvulabs/dialer`.

## Build / run
- There is **no `gradlew` wrapper**. Use the system gradle. On this machine:
  - `gradle :app:assembleDebug --offline` (system gradle), or if that is broken (Arch ships a known-bad `/usr/share/java/gradle`), use the full distribution:
    `gradle :app:assembleDebug`
  - Vendored BlackBox native code is built as part of `:app:assembleDebug`; to check that module alone use `gradle :Bcore:compileDebugJavaWithJavac --offline`.
  - `ANDROID_HOME=/opt/android-sdk` is already set.
- Debug APK → `app/build/outputs/apk/debug/app-debug.apk`.
- Debug signing uses the committed `debug.keystore` (alias `androiddebugkey` / password `android`). Release signing needs env vars `KEYSTORE_PATH`, `STORE_PASSWORD`, `KEY_PASSWORD` (see `app/build.gradle.kts`).
- **Release builds are minified/shrunk** (`isMinifyEnabled = true`, `isShrinkResources = true`). `proguard-rules.pro` keeps GeckoView, yt-dlp, vendored BlackBox APIs, `@JavascriptInterface` methods, Room DB implementations, native methods and the persisted `CallType` enum. This R8 configuration has **not** been runtime-validated on-device; treat a release-only crash as a keep-rule regression first.
- **Do not remove `kotlin.compiler.execution.strategy=daemon`** from `gradle.properties`: `in-process` breaks under Gradle 9.7 (Compose compiler plugin `AbstractMethodError`).
- `googleServices.missing.passthrough=true` means the app builds without `google-services.json`; don't add one.

## Build constraints (do not "fix")
- APK ships **arm64-v8a only** (`abiFilters`). Explicit choice to keep APK ~300 MB; GeckoView dominates.
- Vendored `Bcore` uses NDK `27.1.12297006`; the installed `27.0.12077973` is incomplete and fails the native build. Its `Application.mk` is pinned to `arm64-v8a`.
- `useLegacyPackaging = true` is required or yt-dlp's bundled Python/FFmpeg cannot run (native libs must be extracted from the APK).
- **Dependency cleanup (2026-10-27):** removed `androidx.navigation.compose`, WorkManager, Moshi/Retrofit/logging-interceptor, Firebase AppCheck and the duplicate Coil declaration. **Keep `implementation(platform(libs.firebase.bom))`** even though Firestore/Auth remain commented out: ML Kit's transitive `firebase-encoders`/`firebase-annotations` need the BOM for version alignment, and removing it breaks offline dependency resolution.

## Architecture
- Modules are `:app`, `:Bcore`, `:black-reflection` and `:compiler`; namespace `com.example`, package `com.example` (dialer app, despite the name). `MainActivity.kt` routes everything: a launcher-style **Home** grid (the default landing screen) plus a **swipeable launcher pager** (`LauncherPager`) with optional pages — **App Drawer / Recent / System Tools / Quick Toggles / Now Playing / Dashboard** — all togglable from Launcher Settings, and a **Phone** screen (Recents/Contacts/SMS), **navigated from the Home grid tiles** (the bottom dock was removed 2026-10-23 — see the main-surface bullet), plus an `immersiveAppId` full-screen switch for per-tool screens (files, web, audio, samba, camera, etc.). New tools = add a new `com.example.ui.screens/<name>/<Name>Screen.kt` and a case in the `when (immersiveAppId)` block + top-bar title map in `MainActivity.kt`. **The launcher catalog lives in `ui/screens/apps/AppCatalog.kt`** (`AppItem`, `APPS` — the `"sys"` System Tools tile was removed on 2026-10-23, its contents now lead the swipe-left page — `TOOLS`, `WEB_APPS`, and the flat `LAUNCHER_SECTIONS` = core comms + APPS + TOOLS + WEB_APPS + Terminal/Launcher-Settings/Settings); the old `AppsHubScreen`/`ToolsHubScreen`/`WebAppsScreen` composables still compile and share those lists but are **no longer wired into `MainActivity`** (kept for reference, not deleted). **The tools** (`ui/screens/apps/ToolsHubScreen.kt`, now unwired — the Home grid is the launcher) are the utilities that used to be buried in the File Manager's ⋮ menu (Samba, Wi-Fi Transfer, Text Extract, APK Backup, Phone Info, Recycle bin) and inside System Tools (Flashlight, Sound Recorder, Calculator), plus Internet Radio (which used to open only inside Audio Player), The VNC Viewer tile for the local Linux desktop has been removed from the Home grid; it remains available for external VNC server connections only. **BT Mouse & Keyboard** (added 2026-10-30). **Screen Recorder** (added 2026-11-23) is a Tools tile just after Sound Recorder: `ScreenRecorderScreen` requests `MediaProjection` from its Activity, then `ScreenRecorderService` records silent H.264 MP4 by default with an optional AAC mic toggle (no internal playback capture) to `Movies/NJ-Dialer/Screen Recordings`; it is a `mediaProjection|microphone` foreground service with notification Stop. The same route is exposed as an inline Assistant Quick card; its MediaProjection consent goes through transparent `ScreenRecorderConsentActivity`, never a full-screen recorder UI. The full-screen app has no Back button (system gesture only) and uses `FloatingTopBar(useGlass = viewModel.useGlassmorphism.value)` plus translucent card/root backgrounds. Do not add a Quick Settings shortcut for it. Tile order is deliberate: **Bible is the FIRST tile with Nyimbo (the Chichewa hymnal) immediately after it** (the two reading apps are grouped at the top), **Internet Radio sits just after Sound Recorder**, and **BT Mouse & Keyboard sits just after Calculator**. On 2026-10-16 the user swapped the Bible and Recycle-bin tiles between the two hubs: **Bible moved here from the Apps Hub and Recycle bin left this tab for the Apps Hub** (so Recycle bin — the undo path for a delete — is now launched from the Apps Hub, not the Tools tab). Every tile just sets `immersiveAppId` to its existing route (all are plain immersive ids, so `onLaunchApp = { immersiveAppId = it }`, no `toolReturnToFiles`: back from a tool returns to the launcher/Phone surface). Note the persisted semantics shifted again with the launcher model: old `last_tab` `0` migrates to Phone, old `1/2/3` (hubs) migrate to Home, and the live keys are now `last_screen`/`last_phone_tab` (one-time, self-healing). **Catalog additions (2026-10-27):** the Home grid now exposes `downloads` (a normal-inset alias of `DownloadsScreen`, distinct from the browser-only `browserdownloads` immersive route), `vault`, `callstats` and `contacttools` (the latter two in Comms); the existing `downloader` id is unchanged but its visible title is **“Video Downloader”** so it is not confused with the new Downloads manager. `WEB_APPS` also gained **Drive, Docs, Gmail, Claude and Grok**; `launchById` routes every registered `webAppModule(id)` to `GeckoWebAppActivity` rather than keeping a hardcoded id list. The newly exposed native screens deliberately have **no on-screen Back button** — Downloads, Vault, Call Stats and Contact Tools rely on the system back gesture/`MainActivity` handler. `CallStatsScreen` retains an `onClose` callback for its embedded use in `CallHistoryScreen` and installs a `BackHandler` there; `ContactToolsScreen` has no callback and relies on the hosting Dialog/`MainActivity` for dismissal. `DownloadsScreen` keeps its own `BackHandler` only to clear search or selection mode before the route closes.
- **APK Sandbox (2026-11-23, vendored BlackBox)** — `ui/screens/sandbox/SandboxScreen.kt` plus the `"sandbox"` Tools tile (`AppCatalog.TOOLS`) and immersive `MainActivity` route let the user pick an APK with SAF, install it into a virtual Android environment, then launch/stop/clear/info/remove it. `NjApp` owns BlackBox setup for the main, `:black` and `:p<number>` processes; `CrashLog.saveSandboxReport(...)` writes Info/diagnostics and raw BBDiag/CrashMonitor logs to `Download/NJCrash/`. `Bcore/.../core/env/SharedStorageConfig.java` persists per-app shared-folder opt-ins under `BEnvironment.getSystemDir()`; `BlackBoxCore.get().setSharedInternalStorageAccess(pkg,user,enabled)` / `hasSharedInternalStorageAccess(pkg,user)` expose it, and `IOCore.enableRedirect()` adds black rules only for `Download`, `Documents`, `DCIM`, `Movies`, `Music`, `Pictures` when opted in (never default virtual storage) and creates six empty placeholder dirs in the virtual external root so simple file managers list them. `IOCore.redirectPath()` must return the full original path for a black-rule match with a path-boundary check, because `TrieTree.search()` returns only the matched prefix. SAF content URIs are bridged separately: `IActivityManagerProxy.GetContentProvider` acquires the real `com.android.externalstorage.documents` provider as the host when that opt-in is on, `ContentProviderDelegate.update()` wraps it in `SafProviderStub`, and `grantUriPermission`/`revokeUriPermission` rewrite target package+uid so persisted URI permissions land on the host; the stub must preserve all `String` args (unlike `SystemProviderStub`/`ContentProviderStub`) because they carry authority/method/arg for `DocumentsContract`. Do not hook `DocumentsContract` static methods (URI builders/parsers only). `BlackBoxCore.DIAG_BUILD` is `bb-4.0.9-shortcuts`. Toggling storage stops the sandbox package and requires relaunch; shared folders are not private because the sandbox shares NJ-Dialer's UID/permissions. Do not clear BBDiag crash files on launch — `BlackBoxCore.launchApk()` keeps the previous raw crash history so the export can capture it. The vendored modules are `:Bcore`, `:black-reflection` and `:compiler`; upstream source-of-truth is `https://github.com/a1-tools/black-box`. `Bcore` is deliberately pruned (no blanket permission list, no `ProxyVpnService`, launcher activity restored, `specialUse` FGS subtypes), `Bcore/consumer-rules.pro` + app `proguard-rules.pro` carry the R8 keeps, and `BActivityThread.installVirtualClassLoader(...)` builds a `PathClassLoader` from the installed APK plus its split APKs/native libraries and sets `LoadedApk.mClassLoader`/`mDefaultClassLoader`. The classloader parent MUST stay the boot classloader (`Object.class.getClassLoader()`, falling back to the system classloader) — a host/NJ-Dialer parent loads the host's AndroidX classes first and produces `VerifyError` (`androidx.appcompat.app.c` / `androidx.core.app.e`) in sandboxed apps with bundled AndroidX. On-device verified with a small notes APK after that fix. Sandboxed apps run in `:sandbox0`, which is process isolation only, **not** a security boundary (same UID/permissions); GMS/banking/Play Integrity/anti-tamper and 32-bit-only native APKs are expected to fail. Launched sandboxed activities are forced immersive by `Bcore/src/main/java/top/niunaijun/blackbox/utils/compat/ImmersiveCompat.java` from `AppInstrumentation` create/resume/new-intent hooks; API 30+ uses `WindowInsetsController` with `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`, API 26–29 uses legacy immersive-sticky flags, and the helper is gated by `BlackBoxCore.get().isBlackProcess()` so host screens are unaffected. Do not add a boot receiver or hidden keep-alive.
- **Balanced performance profile (2026-10-27)** — reduces idle RAM/CPU on the low-RAM HiOS phone without changing features. Keep these rules when editing:
  - **No background YtDlp warm-up.** `NjApp` installs `CrashLog` and initializes BlackBox only; `QuickDownloadDialog.show()` calls `YtDlp.warmUp(activity.applicationContext)` so the ~29 MB Python/FFmpeg extraction happens on the download path instead of in every private process at launch.
  - **Daily temp cleanup is not WorkManager.** `util/TempCleanup.runIfDue(context, 24h)` prunes stale `cacheDir` and `filesDir/Camera`; `MainActivity` runs it ~30 s after launch on `lifecycleScope` + IO. `TempCleanupWorker.kt` was deleted; do not reintroduce WorkManager just for cleanup.
  - **Lifecycle-aware tickers.** Clock, Now Playing, Downloads/VideoDownloader refresh, FileManager safety refresh and audio/video position pollers use `LocalLifecycleOwner` + `repeatOnLifecycle(STARTED)`. Media pollers use 250 ms while playing and 1000 ms paused; download polling stays at 2 s while visible, and `DownloadManager.attach` stays outside the loop. Do not revert to unconditional `while (true)` / 1 s polling.
  - **Gated contact subscription.** `LauncherHomeScreen` collects `combinedContacts` only while the search query is non-blank and uses root `favoriteContacts` for the favourites shelf; the root no longer collects the full call log/contact list for badges.
  - **Media index is stale-while-revalidate.** `MainViewModel.refreshMediaIndex(force)` skips scans under 5 minutes, refreshes on resume but not eagerly at startup, and keeps the last good index on failure. Scan roots are targeted (`MediaStore` plus `filesDir/Camera`, `filesDir/Recordings`, external volumes) with extension sniffing/filtering to exclude non-media. Manual refresh buttons must keep `force = true`.
  - **Contacts/call log are throttled/incremental.** Contacts refresh at most every 10 minutes with a debounced content observer; call-log import uses `call_log_last_sync` with a ±2-minute overlap and falls back to a full import when the cursor is missing. The missed-call badge is a Room count, not a live full-log collection.
  - **Keep-alive expiry is opt-in.** `util/KeepAliveTimeout` stores `timeout_min` in `keep_alive_config` (`0` = never, options 15/30/60/120); both keep-alive services schedule a `Handler` timeout after `startForeground` and cancel it on `ACTION_STOP`/`onDestroy`. Settings exposes it under “App Behavior”. The timeout is read at service start; changing it does not reschedule an already-running service.
- **Landscape / wide-window layout (2026-11-07):** wide/landscape content is constrained to reduce stretching and dead space while preserving portrait behavior and full-bleed/immersive surfaces. `ui/components/AppComponents.kt` defines `AppContentMaxWidth = 840.dp` and `Modifier.landscapeContentWidth(...)`, and `FloatingTopBar` applies `WindowInsets.safeDrawing.only(Horizontal)` (glass + non-glass). Native list/tool screens use `landscapeContentWidth()` on their main scroll containers; `LauncherHomeScreen` uses safe-drawing start/end padding and adapts to `GridCells.Adaptive(84.dp)` in very wide landscape (`screenWidthDp >= 700` or Auto columns) while keeping explicit 4/5/6/list baselines. Gecko chrome is constrained where safe (`GeckoWebAppScreen` bar, `GeckoWebActivity`/`GeckoWebActivity2` raw-View bar) — do not constrain Gecko page content, camera/terminal canvas, image/video/document viewer media, or other intentionally full-bleed surfaces; respect the existing `shouldBeImmersive`/`innerPadding` edge-to-edge contract.

This is what made short messages duplicate far more often than long ones.
